 ## 討論：推理過程回顧功能設計 
 
 你的設想方向很清楚，是一個典型的 **undo/redo 時間軸** 模型。但在深入設計前，有幾個關鍵問題需要釐清。 
 ────── 
 ### 🔑 問題一：「步驟」的定義粒度 
 
 **當前的 autoSolveStepByStep 在一次呼叫裡可能填入十幾個格子**（跨多個 loop），每個格子各自是一個 `ReasoningItem`。 
 
 • **選項 A（細粒度）**：每一個特徵值填入 = 一個步驟。自動推理產生 10 個格子 = 10 個步驟。回顧時可以一格一格回退。 
 • **選項 B（粗粒度）**：自動推理的整批結果 = 一個「複合步驟」。手動操作每次 = 一個步驟。回顧時一整批自動推理可以一次 undo。 
 
 你傾向哪種方式？ 
 ────── 
 ### 🔑 問題二：`userGrid` 要如何從歷史重建？ 
 
 這是最關鍵的技術問題。 
 
 回退到某個步驟，需要重建當時的 `userGrid`。目前 `ReasoningItem` 記錄了 `feature`（名稱字串）、`value`、`position`，**但沒有記錄 `featureIndex`（第幾個特徵類別）**。 
 
 要從 `past` 陣列重建 `userGrid`，有兩個方案： 
 
 • **方案 A（推薦）**：在 `ReasoningItem` 新增 `featureIndex: number` 欄位，這樣回退時可以直接從 `past[0..n]` 逐步套用重建出 grid。 
 • **方案 B**：每個步驟快照整個 `userGrid`（記憶體消耗較大，實作簡單）。 
 
 你偏好哪種？ 
 ────── 
 ### 🔑 問題三：「修改推理依據規則」是否也是一個可回退的步驟？ 
 
 目前手動推理項目可以： 
 
 • 新增/刪除依據規則 
 • 替換依據規則（下拉選單） 
 
 這些操作**只影響 `rules` 欄位（推理依據文字）**，不影響 `userGrid`（解答格子的值）。 
 
 你的設想裡，修改依據規則算不算一個可以 undo 的「步驟」？ 
 
 我的判斷：**不需要**。因為 undo/redo 的核心目的是回退「解答填入」的狀態，而不是回退「推理依據說明文字」。若把依據編輯也納入，系統會變得很複雜。 
 
 你認同嗎？ 
 ────── 
 ### 🔑 問題四：「重置」按鈕的行為 
 
 目前解答區有「重置」按鈕，呼叫 `initUserGrid()` 清空一切。 
 
 引入 undo/redo 後： 
 
 • **選項 A**：重置清空所有歷史（past 和 future 都清空）。 
 • **選項 B**：重置本身算一個步驟，加入 past，可以被 undo（亦即 undo 重置 = 恢復到重置前的狀態）。 
 
 你希望哪種行為？ 
 ────── 
 ### 🔑 問題五：下表（future）需要顯示哪些資訊？ 
 
 上表（past）現在有：編號按鈕、推理結果描述、推理依據規則（可編輯）。 
 
 下表（future）是「已被撤回的步驟」，顯示時應該： 
 
 • **選項 A（簡化）**：只顯示編號按鈕 + 描述，不顯示推理依據（因為那些步驟目前還不「生效」）。 
 • **選項 B（完整）**：和上表一樣顯示全部資訊（但依據規則唯讀，不能編輯）。 
 ────── 
 ### 🔑 問題六：`findHistoryItem` 的範圍 
 
 現有 `state.reasoningHistory` 是單一陣列，`findHistoryItem` 在其中找 item。 
 
 拆分後變成 `past` + `future` 兩個陣列。像 `onHistoryRuleChange`、`addHistoryRule`、`deleteHistoryRule` 這些函式目前針對的是 `past` 中的項目（因為只有 `past` 中的步驟才「生效」、才能編輯依據）。 
 
 確認：只有 `past` 中的項目可以編輯依據規則，future 的項目唯讀，對嗎？ 
 ────── 
 ### 💡 我的整體建議 
 
 在你確認以上問題後，我傾向以下設計方向： 
 ```ts
 // 修改後的 State 
 export interface State { 
  entityCount: number; 
  features: Feature[]; 
  rules: Rule[]; 
  userGrid: Grid; // 仍保留，由 past 推算，但作為 cache 存在 
  past: ReasoningItem[]; // 已完成的步驟（舊 reasoningHistory） 
  future: ReasoningItem[]; // 已撤回的步驟 
  nextReasoningId: number; 
 } 
 
 // ReasoningItem 新增 featureIndex 
 export interface ReasoningItem { 
  id: number; 
  featureIndex: number; // 新增，用於重建 grid 
  feature: string; 
  value: FeatureValue; 
  position: Position; 
  desc: string; 
  rules: RuleDescription[]; 
  isAuto: boolean; 
 } 
 ```
 重建 grid 的函式（回退時用）： 
 ```ts
 function rebuildGridFromPast(past: ReasoningItem[]): Grid { 
  const grid = emptyGrid(); // 建立全空 grid 
    for (const item of past) { 
      grid[item.featureIndex][item.position] = { 
        value: item.value, 
        reasoningId: item.id, 
      }; 
  } 
  return grid; 
 } 
 ```
 回退到某步驟之前（點擊 past 中編號 N 的按鈕）： 
 ```
  找到 past 中 item N 的 index i 
  移除 past[i..end] → 倒序推入 future 最前方 
  userGrid = rebuildGridFromPast(新的 past) 
  重新渲染 
 ```
 快進到某步驟之後（點擊 future 中編號 N 的按鈕）： 
 ```
  找到 future 中 item N 的 index i 
  移除 future[0..i] → 推入 past 末尾 
  userGrid = rebuildGridFromPast(新的 past) 
  重新渲染 
 ```
